# 异常状态 - 未到货

> 通用排查命令与字段说明见 [SKILL.md](../SKILL.md)
>
> **SLA**：触发后 24h 内启动排查，48h 内给出处理方案。
> **责任人**：采购专员。

## 异常说明
- **定义**：快递已发货，在未签收的情况下，物流轨迹 ≥ 72h 未更新。
- **典型成因**：
  - 物流中转滞留（快递网点爆仓、分拨中心积压）
  - 快递包裹丢件
  - 疫情/极端天气等不可抗力导致运输中断
  - 地址信息错误，快递无法派送

## 问题排查步骤

1. **查询物流轨迹**：
   ```bash
   hypersku-cli logistics tracking <trackingNumber>
   ```
2. **分析停滞位置**：

| 停滞节点 | 可能原因 | 动作 |
|------|------|------|
| 揽收后无后续 | 网点积压/包裹未发出 | 联系发件网点确认 |
| 中转中心停滞 | 分拨积压/包裹卡关 | 联系物流客服查询 |
| 派件网点停滞 | 地址问题/网点异常 | 核对收货地址，联系派件员 |

3. **核对收货地址**：确认订单收货地址与仓库地址是否一致。
4. **查看留言**：
   ```bash
   hypersku-cli domestic-third-trade-exception message-list <monitorOrderId> <monitorLogisticsId>
   ```

## 下一步处理步骤

| 序号 | 动作 | 说明 |
|------|------|------|
| 1 | **联系物流承运商** | 拨打快递官方客服，提供运单号查询包裹状态 |
| 2 | **同时联系商家** | 让商家从发件端同步催促物流 |
| 3 | **确认丢件** | 如物流确认丢件 → 跳转 [07-lost-item.md](07-lost-item.md) |
| 4 | **补发/退款** | 包裹短期无法送达 → 联系商家补发或退款，启动换采 |

### 闭环条件
- 物流恢复更新且最终送达 → 异常关闭
- 确认丢件后完成退款/补发 → 异常关闭（转入丢件流程闭环）
