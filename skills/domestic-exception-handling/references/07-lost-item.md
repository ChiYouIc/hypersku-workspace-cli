# 异常状态 - 丢件

> 通用排查命令与字段说明见 [SKILL.md](../SKILL.md)
>
> **SLA**：确认丢件后 72h 内完成与供应商沟通，7 天内完成退款/补发。
> **责任人**：采购专员。

## 异常说明
- **定义**：快递确认丢件，包裹在运输途中丢失。
- **典型成因**：物流承运商运输/中转过程中包裹丢失。
- **与其他异常的区别**：
  - 本状态为物流承运商确认丢件（快递官方定责）
  - "未到货"中若物流确认丢件，应转入本状态处理
  - "未入库/丢包裹"是仓库端的丢失，本状态是运输端的丢失

## 问题排查步骤

1. **查询物流轨迹，确认丢件记录**：
   ```bash
   hypersku-cli logistics tracking <trackingNumber>
   ```
   查看轨迹中是否有"丢件""遗失""理赔"等标注。

2. **确认签收/入库状态**：检查仓库是否实际已签收或入库（排除系统状态不同步）。

3. **联系物流客服确认**：拨打快递官方客服电话，确认丢件定责状态和理赔流程。

## 下一步处理步骤

| 序号 | 动作 | 说明 |
|------|------|------|
| 1 | **联系商家协商** | 告知包裹丢件，协商补发或退款方案 |
| 2 | **商家补发** | 要求商家重新发货（优先方案，时效最快） |
| 3 | **发起退款** | 商家无法补发 → 在 1688 平台发起退款 |
| 4 | **换采** | 退款同时换供应商下单 |
| 5 | **物流理赔跟进** | 联系物流客服提交理赔申请，跟踪赔付进度 |

### 闭环条件
- 商家补发且有正常物流轨迹 → 异常关闭
- 退款到账 + 理赔完成 + 换采完成 → 异常关闭
