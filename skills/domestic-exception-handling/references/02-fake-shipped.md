# 异常状态 - 假发货

> 通用排查命令与字段说明见 [README.md](../README.md)
>
> **SLA**：触发后 24h 内联系供应商，48h 内给出处理方案（确认发货/退款）。
> **责任人**：采购专员。

## 异常说明
- **定义**：第三方采购交易已同步物流单号，但发货时间 ≥ 24h 仍无物流轨迹。
- **典型成因**：
  - 商家虚假发货（填了单号但未实际发出）
  - 包裹已交给快递但未扫描揽收（快递网点积压）
  - 物流单号填写错误（串号/废号）

## 问题排查步骤

1. **查询物流轨迹**：
   ```bash
   hypersku-cli logistics tracking <trackingNumber>
   ```
2. **根据轨迹结果分支判断**：

| 轨迹状态 | 判定 | 动作 |
|------|------|------|
| 无任何记录 | 高度疑似假发货 | 立即联系商家确认是否真实发货 |
| 已揽收但无后续 | 物流延迟/积压 | 联系物流承运商确认，观察 24h |
| 单号不存在/无效 | 商家填错单号 | 联系商家核实正确单号，更正系统 |
| 轨迹显示"退件" | 包裹退回 | 跳转 [06-returned.md](06-returned.md) 退件流程 |

3. **查看留言记录**：
   ```bash
   hypersku-cli domestic-third-trade-exception message-list <monitorOrderId> <monitorLogisticsId>
   ```

## 下一步处理步骤

| 序号 | 动作 | 说明 |
|------|------|------|
| 1 | **联系商家核实** | 通过 1688 旺旺/电话确认包裹真实状态 |
| 2 | **商家确认已发货** | 要求商家提供发货凭证，持续跟踪物流更新 |
| 3 | **商家承认未发/不回复** | 发起 1688 平台退款，理由选择"虚假发货" |
| 4 | **物流单号错误** | 让商家提供正确单号，采购在系统更新物流单号 |

### 闭环条件
- 物流轨迹正常更新（有揽收+运输记录） → 异常关闭
- 退款到账 → 异常关闭（如需换采则跟进换采流程）
