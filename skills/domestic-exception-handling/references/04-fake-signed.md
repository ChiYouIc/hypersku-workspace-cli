# 异常状态 - 假签收

> 通用排查命令与字段说明见 [SKILL.md](../SKILL.md)
>
> **SLA**：触发后 24h 内启动排查，48h 内给出处理方案。
> **责任人**：采购专员（联系供应商/物流），仓库人员（配合确认签收状态）。

## 异常说明
- **定义**：快递显示已签收 ≥ 72h，但仓库显示未签收。
- **与"未签收"的关系**："未签收"超过 72h 未解决则自动升级为本状态。
- **典型成因**：
  - 物流承运商虚假签收（快递员自行签收）
  - 商家填写的收货地址不是仓库地址
  - 包裹送到了错误的地址/签收人
  - 仓库已签收但未在系统录入

## 问题排查步骤

1. **查询物流轨迹**：
   ```bash
   hypersku-cli logistics tracking <trackingNumber>
   ```
2. **核对签收信息**：

| 排查项 | 问题 | 动作 |
|------|------|------|
| 签收地址 vs 仓库地址 | 不一致 | 联系商家确认是否发错地址 |
| 签收人姓名 | 非仓库人员 | 联系物流核实谁签收的 |
| 签收时间 | — | 提供给仓库做对照查询 |

3. **联系仓库确认**：
   ```bash
   hypersku-cli warehouse tracking <trackingNumber>
   ```
   - 让仓库按运单号和签收时间排查是否漏入库。

4. **查看留言**：
   ```bash
   hypersku-cli domestic-third-trade-exception message-list <monitorOrderId> <monitorLogisticsId>
   ```

## 下一步处理步骤

| 序号 | 动作 | 说明 |
|------|------|------|
| 1 | **联系物流核实签收** | 打快递客服确认实际签收地点和签收人 |
| 2 | **联系仓库确认是否漏入库** | 仓库按运单号+签收时间倒查入库记录 |
| 3 | **签收地址错误** | 联系商家确认是否发错地址；如已发错→协商退款/补发 |
| 4 | **仓库漏入库** | 仓库补录入库操作，异常关闭 |
| 5 | **物流虚假签收/包裹丢失** | 向物流发起投诉/理赔，同时联系商家补发或退款，启动换采 |

### 闭环条件
- 仓库确认入库 → 异常关闭
- 确认包裹丢失后完成退款/理赔/换采 → 异常关闭
