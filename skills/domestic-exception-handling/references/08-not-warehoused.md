# 异常状态 - 未入库（含升级：丢包裹）

> 通用排查命令与字段说明见 [README.md](../README.md)
>
> **SLA**：触发后 24h 内联系仓库确认，48h 内确认包裹状态；升级为丢包裹后 7 天内完成赔偿/换采。
> **责任人**：采购专员（主责），仓库人员（确认包裹状态、赔偿协商）。

## 异常说明

本异常为两阶段升级关系：

| 阶段 | 状态 | 触发条件 | 含义 |
|------|------|------|------|
| 第一阶段 | **未入库** | 仓库签收 ≥ 24h，未入库 | 仓库操作延迟或包裹待上架 |
| 第二阶段 | **丢包裹** | 仓库签收 ≥ 72h，仍未入库 | 从"未入库"升级而来，包裹在仓库端丢失 |

- **典型成因**：仓库入库操作不及时、包裹在仓库内丢失、包裹标签脱落无法匹配订单。

## 问题排查步骤

### 第一阶段：未入库

1. **查询仓库包裹状态**：
   ```bash
   hypersku-cli warehouse tracking <trackingNumber>
   ```
2. **联系仓库确认**：提供运单号，让仓库按签收记录倒查包裹位置。
3. **判断结果**：

| 仓库反馈 | 动作 |
|------|------|
| 包裹在仓，待上架/入库中 | 记录反馈，持续跟踪；如 48h 仍未入库，再次催促 |
| 包裹找不到 | 进入第二阶段预警，仓库内部排查 |
| 仓库确认丢失 | 直接按第二阶段（丢包裹）处理 |

### 第二阶段：丢包裹（由"未入库"升级）

> 到达此阶段说明仓库端确认包裹丢失或超过 72h 仍未入库。

1. 要求仓库出具**包裹丢失确认说明**（作为理赔/记录凭证）。
2. 同时执行以下两项：

| 动作 | 说明 |
|------|------|
| 与仓库协商赔偿 | 按包裹货值协商赔偿方案 |
| 联系商家补发/换采 | 仓库赔偿周期长，优先向商家补发或换采保履约 |

## 下一步处理步骤

### 采购专员执行

| 序号 | 动作 | 适用阶段 | 说明 |
|------|------|------|------|
| 1 | **联系仓库确认** | 第一阶段 | 提供运单号，确认包裹是否在仓 |
| 2 | **催促入库** | 第一阶段 | 包裹在仓→催促仓库尽快入库上架 |
| 3 | **要求仓库出具丢件说明** | 第二阶段 | 仓库确认丢失→要求书面确认作为凭证 |
| 4 | **与仓库协商赔偿** | 第二阶段 | 按货值协商赔偿金额和周期 |
| 5 | **联系商家补发或换采** | 第二阶段 | 仓库赔偿周期不可控，优先联系商家补发保障履约 |

### 闭环条件
- 仓库入库完成 → 异常关闭
- 仓库赔偿到账 + 换采完成 → 异常关闭
- 商家补发且有正常物流轨迹 → 异常关闭
