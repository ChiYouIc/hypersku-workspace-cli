# 异常状态 - 未签收

> 通用排查命令与字段说明见 [README.md](../README.md)
>
> **SLA**：触发后 24h 内启动排查，48h 内给出处理方案。**需争取在 72h 内闭环，否则将升级为"假签收"**。
> **责任人**：采购专员（主责），仓库人员（配合确认）。

## 异常说明
- **定义**：快递显示已签收 24~72h，仓库显示未签收。
- **升级关系**：超过 72h 仍未解决 → 自动升级为 [假签收](04-fake-signed.md)，处理动作加重。
- **典型成因**：
  - 快递刚签收，仓库尚未录入系统（正常延迟）
  - 商家发错收货地址
  - 快递自动签收/提前签收
  - 包裹异常（破损被退回等）

## 问题排查步骤

1. **查询仓库状态**：
   ```bash
   hypersku-cli warehouse tracking <trackingNumber>
   ```
2. **查询物流轨迹**：
   ```bash
   hypersku-cli logistics tracking <trackingNumber>
   ```
3. **核对签收地址**：签收地址与仓库地址是否一致。
4. **查看仓库备注**：
   ```bash
   hypersku-cli domestic-third-trade-exception message-list <monitorOrderId> <monitorLogisticsId>
   ```

## 下一步处理步骤

| 序号 | 动作 | 说明 |
|------|------|------|
| 1 | **联系仓库确认签收** | 提供运单号让仓库查是否已收到包裹但未录入系统 |
| 2 | **仓库已收到** | 催促仓库尽快录入签收，异常关闭 |
| 3 | **仓库未收到** | 联系物流/商家确认包裹去向，按结果处理 |
| 4 | **签收地址不符** | 联系商家确认发货地址，协调物流转寄或退款 |
| 5 | **包裹丢失** | 联系商家补发或退款，启动换采 |

> ⚠️ **72h 升级预警**：若在触发后 48h 仍无实质进展，采购专员需提前准备升级应对方案（联系物流取证、准备退款材料），确保 72h 前明确根因。

### 闭环条件
- 仓库确认签收 → 异常关闭
- 72h 内未解决 → 自动升级为"假签收"，按 [04-fake-signed.md](04-fake-signed.md) 继续处理
